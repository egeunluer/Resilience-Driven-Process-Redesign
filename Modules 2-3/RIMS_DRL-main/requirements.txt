# Dependencies for the RIMS_DRL training pipeline (train_DRL.py + gym_env.py and
# everything they import: shock.py, process.py, event_trace.py, entities.py,
# role_simulator.py, parameters.py, inter_trigger_timer.py, callbacks.py,
# calibrate_resilience_constants.py, compute_resilience_metrics.py).
#
# Replaces the previous requirements.txt, which was a Windows/conda `pip freeze`
# (embedded `file:///C:/...` build paths) that will not install on Colab or any
# other Linux environment. This file instead lists only the packages the code
# actually imports, pinned to the exact versions verified working end-to-end via
# a real training smoke test this session (Consulta, RESOURCE_REMOVAL +
# DEMAND_SPIKE shocks, MaskablePPO rollout + policy update, no errors).
#
# Notes:
#   - prophet (+ its cmdstanpy backend) is required, not optional: both Consulta
#     and BPI2017 use "custom"-type arrival generation backed by a real trained
#     Prophet model (see each dataset's *_prf.json under RIMS_DRL-main/example/).
#     First import of `prophet` may take a moment while it installs the cmdstan
#     backend; if that fails, run `python -m cmdstanpy.install_cmdstan`.
#   - keras/tensorflow is required, not dead weight: entities.py calls
#     keras.utils.to_categorical for day-of-week one-hot encoding.
#   - torch is pulled in automatically by stable-baselines3/sb3-contrib. Don't
#     pin it separately here -- on Colab, an unpinned install lets pip reuse the
#     GPU-linked torch build Colab ships with, rather than replacing it.
#   - pulp is pinned below 4 because pm4py imports it whenever it is installed
#     (Colab ships it preinstalled), and pulp 4.x's rewrite no longer exports
#     LpStatus, which pm4py 2.7.22.2 imports at load time:
#     "ImportError: cannot import name 'LpStatus' from 'pulp'".
